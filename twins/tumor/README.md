# Tumor twin

Reproduces TumorTwin: a patient-specific reaction–diffusion model of high-grade glioma is calibrated to MRI and then
predicts the tumor under different chemotherapy doses. On dtcore as update, predict and what-if: the patient's MRI
visits arrive one by one and the twin calibrates at each. It has no decision: without a toxicity cost a higher dose
is always better. Not on the page: a what-if takes seconds, not milliseconds.

## Sources
- Kapteyn, Chaudhuri, Lima, Pash, Bravo, Willcox, Yankeelov, Hormuth 2026, *BMC Medical Informatics and Decision
  Making* 26:237 (arXiv 2505.00670).
- OncologyModelingGroup/TumorTwin @ `bedf90a` (2026-04-07), fetched by `fetch_upstream.sh`.
  **UT Austin Research License: academic and research use only.**

## Six elements

| S | O | D | Q | U | R |
|---|---|---|---|---|---|
| 3D tumor cell density | MRI (ADC → cellularity), 10 visits | calibrated (d, k, α_RT, α_CT), point estimate | total tumor cell count over time | chemotherapy dose | none yet (no toxicity cost) |

## Files
- `model.py`, `sources.py`, `twin.py` — the twin on dtcore: `Glioma` (the authors' model of one patient: solve and
  calibrate), `PatientReplay` (the MRI visits in order), `TumorTwin` (`update`, `predict`, `whatif`).
- `scripts/run_twin.py` — the twin through `dtcore.run` → `results/HGG_demo_001/twin_run_<visits>.json` and `.png`.
- `scripts/repro_hgg.py` — the upstream HGG demo tutorial as a script → `results/HGG_demo_001/repro.json`.
- `scripts/sample_sims.py`, `merge_sims.py`, `surrogate_experiments.py` — training simulations and a Gaussian-process
  surrogate (in progress).
- `hpg/` — Slurm job scripts and a guide for running the simulations on a cluster.
- `experiments/2026-10-13_pilot_inverse/` — can a small network read the parameters straight from MRI summaries?

## Setup (PyTorch, Python 3.10–3.11)
The authors' package pins `numpy==1.23.5`. In an environment that already has PyTorch and a newer NumPy, install it
without its pins; with NumPy 2.4 the model still gives the saved reproduction's counts within 0.1 %
(`tests/test_tumor.py`, skipped without the package or the fetched upstream):
```bash
cd twins/tumor
./fetch_upstream.sh
pip install torchdiffeq nibabel pydantic pydantic-settings scikit-learn
pip install --no-deps -e upstream/TumorTwin
```
Or, in an environment of its own: `pip install torch scikit-learn -e upstream/TumorTwin`.

## Run
The twin, from the repository root:
```bash
python twins/tumor/scripts/run_twin.py --visits 5    # the first 5 MRIs, ~13 min on a laptop CPU
python twins/tumor/scripts/run_twin.py               # all 10 MRIs, ~35 min
python -m pytest tests/test_tumor.py                 # ~1 min
```
An observation is one visit: `t` (days since the first MRI), `visit` (its number) and `cell_count` (from the MRI).
The twin sends no action.

The reproduction and the surrogate, from `twins/tumor`:
```bash
python scripts/repro_hgg.py HGG_demo_001         # ~31 min on 2 CPU cores
python scripts/sample_sims.py --n 256 --seed 0   # training simulations, ~2 h on 2 cores (cluster: hpg/README.md)
python scripts/sample_sims.py --truth            # the true parameters at each dose: the reference decision
python scripts/surrogate_experiments.py          # train the surrogate, calibrate with it, data-size experiment
```

## Results (HGG_demo_001)
- Calibrating 4 parameters (d, k, α_RT, chemo sensitivity) on the first 5 MRIs gives (0.1000, 0.0500, 0.0500, 0.2001)
  against the true (0.1, 0.05, 0.05, 0.2): error < 0.03 %.
- Total cell count at visits 6–10 (not used for calibration) is predicted within 0.01 %.
- Total chemo dose 30 → 70: cell count on day 270 falls from 3.17e11 to 2.31e11, monotonically.

The twin (`scripts/run_twin.py`), which calibrates again at every visit from the parameters it had:
- Before the visit on day 30 it expects a count 10 % too high, and before day 60 one 23 % too low: treatment began
  on day 26, so the one MRI it has seen since is four days into it. Calibrated on the first 3 MRIs it has the true
  parameters to four decimals, and from then on it expects each count to within 0.03 % (`twin_run_10.json`).
- After 5 visits it forecasts the counts of visits 6 to 10 to within 0.01 %, and its what-if over the chemo dose is
  within 0.02 % of the reproduction's five numbers (`twin_run_5.json`).
- The grid is cropped around the tumor seen at the last visit, as in the tutorial, so the region modeled is known
  from the start. The twin gets the densities visit by visit.

## Notes
- The demo data are generated by the same model without noise (the paper: "idealized … no noise in the calibration
  data"), so these accuracies do not carry over to real patients.
- Cell 22 of the upstream tutorial swaps the parameter labels: parameter 0 is d, not k (see the unpacking order in
  `update_model_and_predict`).
- `ChemotherapySpecification` renormalises by the largest single dose in its constructor: construct it first, then
  change `ct.doses`.
